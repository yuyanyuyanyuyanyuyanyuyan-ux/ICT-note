# 第三章 云中的存储

## 一、对象存储服务 OBS

对象存储服务（Object Storage Service，OBS）是一种完全托管的存储服务，理论上无空间上限，但单个对象（文件）最大不能超过 48TB。它适合存放图片、视频、日志、备份等非结构化数据，并且支持事件触发（例如上传文件后自动触发函数处理），同时提供多种存储级别以降低不同场景下的成本。

### 1. OBS 存储桶

OBS 中数据存放在“桶”（Bucket）里，桶是顶层命名空间。桶内可以存放任意数量的对象（Object）。对象一旦写入，只能整体覆盖更新，不能像传统文件系统那样进行部分修改；对象可读，但不可直接修改内容。

### 2. 对象标识

每个对象通过“桶名 + 对象名”唯一标识。如果对象名中包含路径分隔符（如 `folder/photo.jpg`），访问 URL 会体现出目录结构，但实际上 OBS 是扁平结构，没有真正的文件目录。

### 3. OBS 权限设置

默认情况下，其他用户通过 URL 直接访问 OBS 对象会被拒绝。权限控制分两层：
- **ACL（访问控制列表）**：粗粒度控制，可以设置桶或对象为公开读、私有等，适合简单场景。
- **桶策略（Bucket Policy）**：细粒度控制，可以指定哪些用户（或所有用户）能对桶执行哪些操作（如读、写、列举），适合复杂权限需求。

### 4. OBS 版本管理

开启版本管理后，对对象的覆盖或删除操作不会真正移除旧数据，而是生成新版本并给旧版本打上删除标记。这样可以防止误删或误覆盖，随时可以恢复到之前的任意版本。

### 5. OBS 归档存储

归档存储适用于重要但不经常访问的数据（如合规存档、历史记录）。它提供高可靠性和极低的存储成本，但读取数据前需要先“解冻”，等待时间从几分钟到几小时不等。注意：归档存储不同于备份，备份通常指数据的可恢复副本，而归档更侧重于长期低成本保存原始数据。

### 6. OBS 存储类型对比

| 存储类型 | 访问频率 | 单价 | 读取延迟 |
|----------|----------|------|----------|
| 标准存储 | 高 | 最高 | 毫秒级 |
| 低频访问 | 较低 | 中等 | 毫秒级 |
| 归档存储 | 极低 | 最低 | 需提前解冻 |

### 7. 典型场景

- **存储备份**：将本地或云上数据备份到 OBS，利用其高耐久性。
- **数据分发数据源**：作为 CDN、大数据平台的数据源，提供高吞吐读取。
- **静态网站托管**：将 HTML、CSS、JS 等静态文件放在 OBS 中，配置为静态网站。
- **数据湖存储目标**：作为数据湖的底层存储，配合分析服务进行数据处理。

### 8. 计价方式

OBS 采用存算分离计费：
- **存储费用**：按实际存储量（GB/月）计费，存多少算多少。
- **流量费用**：上传免费，下载收费；下载到同一区域（如同region的ECS）通常免费。
- **API 调用费用**：按请求次数（如 PUT、GET）计费。

## 二、云硬盘 EVS 与本地硬盘

云硬盘（Elastic Volume Service，EVS）是一种块存储服务，需挂载到云服务器（ECS）使用。EVS 数据会在同一可用区内保存三个副本，保证高可用性；单盘最大容量 32TB。由于三副本仅在一个可用区内，若需跨可用区容灾，可通过 OBS 快照将数据备份到其他可用区。

### 快照功能详解

快照是云硬盘在某个时间点的完整数据备份，可以快速恢复数据或创建新的云硬盘。快照采用增量方式，只保存自上次快照以来变化的数据，因此空间占用小、创建速度快。常见用途：
- 数据误删或损坏后恢复到快照时间点。
- 克隆云硬盘到其他可用区或区域。
- 定期自动快照作为数据保护策略。

### EVS 卷的生命周期

1. **创建**：指定容量、类型（如高IO、通用SSD）和可用区。
2. **挂载**：将 EVS 卷挂载到同一可用区的 ECS 上，作为数据盘或系统盘。
3. **使用**：像普通硬盘一样格式化、分区、读写。
4. **卸载**：在不影响业务的前提下从 ECS 上安全卸载。
5. **扩容**：在线扩容，无需停机，容量扩大后需在操作系统内调整文件系统。
6. **删除**：删除前建议先创建快照备份；删除后数据不可恢复。

### EVS 适用场景

- 操作系统盘（ECS 系统盘）
- 数据库（需要稳定低延迟的块存储）
- 持久化业务应用（如 ERP、CRM）
- 企业敏感数据存储（需要完全控制磁盘）

### 计价

EVS 按申请的整卷容量计费，无论实际使用多少，都按卷大小收费。

## 三、ECS 本地硬盘

ECS 本地硬盘直接挂载在物理宿主机上，具有极低的访问延迟和极高的 IOPS 性能，适合临时缓存、日志等对性能要求高但不要求持久化的场景。**注意**：本地盘数据不可靠，一旦服务器关机、重启或发生故障，数据会丢失，因此不能用于重要数据存储。

## 四、三种存储对比

| 存储类型 | 本质 | 访问方式 | 持久性 | 典型用途 |
|----------|------|----------|--------|----------|
| EVS 云硬盘 | 块存储（硬盘） | 挂载到 ECS，作为磁盘使用 | 高（三副本） | 系统盘、数据库 |
| 本地磁盘 | 块存储（硬盘） | 挂载到 ECS，作为磁盘使用 | 低（关机即失） | 临时缓存、高性能计算 |
| OBS 对象存储 | Web 服务（API 调用） | 通过 HTTP/HTTPS API 访问 | 极高（多AZ冗余） | 备份、归档、静态网站 |

由于 OBS 通过 API 访问，而 EVS/本地盘作为块设备使用，代码层面两者不兼容，应用需根据存储类型选择不同的接口。

## 五、SFS 弹性文件服务

弹性文件服务（Scalable File Service，SFS）提供共享文件存储，支持多个 ECS 同时挂载同一文件系统，实现数据共享。SFS 数据同样保存三副本，容量可弹性扩展，性能随容量线性增长，适合企业文件共享、内容管理、大数据分析等需要多机访问同一份文件的场景。
