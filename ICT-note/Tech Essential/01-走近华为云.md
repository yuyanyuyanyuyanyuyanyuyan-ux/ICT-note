# 1 走近华为云

> 一句话概括：**云计算不是某种技术，而是一种"随时随地、按需自助"使用 IT 资源的模型；华为云把这套模型做成了覆盖全国的公有云服务。**

## 学习目标

- 理解传统 IT（烟囱式架构）的痛点，以及"云化"如何解决这些问题。
- 记住云计算的权威定义（NIST）与定义中的 4 个关键点。
- 分清云计算的 **部署模式**（公有云 / 私有云 / 混合云 / 行业云）与 **服务模式**（IaaS / PaaS / SaaS）。
- 掌握云计算的 **五大价值**。
- 认识三类基础技术：计算（虚拟化 / 容器）、网络（传统网络 / 虚拟网络）、存储（块 / 文件 / 对象）。
- 了解华为云简介、应用场景、三种交付模式、技术支持体系、生态与快速入门（计费方式、Region/AZ、IAM）。

## 1.1 云计算基础知识

### 1.1.1 云计算的背景：传统 IT 的痛点

早期企业 IT 采用 **烟囱式架构**——每个项目/应用各自独立一套基础设施（独立硬件、操作系统），类似"网站服务器""邮件服务器"的说法，指的是服务器上部署的应用类型。

传统 IT 的主要痛点：

- 设备采购周期长，新业务系统上线慢；
- 硬件设备孤立存在，可靠性只能依赖软件侧；
- 设备种类多、厂商多，硬件管理复杂；
- 单个设备性能有限；
- 设备整体利用率不高，企业总成本居高不下。

烟囱式架构的问题：**可靠性不够高（有单点故障风险）、一台设备对应一个应用导致资源利用率低、应用间物理隔离导致数据难以共享。**

云化架构（集群 + 分布式）能显著提高应用可靠性，并能按需使用资源，从根本上解决利用率不高、管理结构复杂等问题。

### 1.1.2 云计算的定义（NIST）

> 云计算是一种**模型**，它可以实现随时随地、便捷地、随需应变地从可配置计算资源共享池中获取所需的资源（例如网络、服务器、存储、应用及服务），资源能够快速供应并释放，使管理资源的工作量和与服务提供商的交互减小到最低限度。（美国国家标准与技术研究院 NIST）

定义中的 4 个重点：

1. 云计算**不是技术，而是一种模型**；
2. 可使用的资源包括**网络、服务器、存储、应用及服务**，目标是"像获取水电一样获取 IT 服务"；
3. "随时随地"的前提是**网络可达**；
4. "资源快速供应并释放"对应**快速弹性伸缩**；"与提供商交互最小化"对应**按需自助服务**。

另一种理解：拆成"云"+"计算"。"云"= 互联网及底层基础设施的抽象体；"计算"= 一台足够强大的计算机提供的计算服务。即 **通过互联网使用强大计算机提供的资源服务，使用量可用统一单位描述。**

### 1.1.3 云计算就在身边

- **百度网盘**：备份、同步、共享 → 云存储服务；
- **个人所得税 APP / 网上办事大厅**：政务云化，打通各部门数据壁垒，实现并联审批、一窗式审批。

### 1.1.4 云计算的模式

#### 部署模式（4 种）

| 模式 | 说明 | 特点 |
| --- | --- | --- |
| 公有云 | 由云服务提供商搭建，资源向公众开放，需依赖互联网 | 最先出现、最被熟知；用户只买资源/服务，硬件与运维由第三方负责 |
| 私有云 | 部署在企业/单位内部，数据保存在自有数据中心 | 数据经入口防火墙，最大限度保护数据；可基于已有架构、利旧设备；但设备会旧、更换有成本，共享少 |
| 混合云 | 包含两种或以上云，业务可按需在几种云上切换 | 灵活；常见用法：私有云把公有云作为灾难转移平台；成本效益好；但设置复杂、整合有挑战、兼容性问题 |
| 行业云 | 面向特定行业的云（本课程主要讲前三种） | — |

> 私有云的新说法：在公有云上购买**专属云**服务，保证用户拥有专属计算/存储资源与高度可靠的隔离网络，满足关键业务高可靠、高性能、高安全要求。

#### 服务模式 IaaS / PaaS / SaaS

分层的概念：**软件层**（应用程序）、**平台层**（OS 之上、应用程序之下的中间件与运行环境）、**基础设施层**（网络/存储/计算资源 + 虚拟化层）。

| 模式 | 云服务商提供 | 用户自营 | 类比（以运行大型单机游戏为例） |
| --- | --- | --- | --- |
| **IaaS** | 基础设施层 | 平台层 + 软件层 | 买云服务器 + 镜像装 OS，自己下载安装游戏软件 |
| **PaaS** | 基础设施层 + 平台层 | 软件层 | 买"已装好 .NET Framework 运行环境"的环境 |
| **SaaS** | 全部 | 无 | 买"已安装并激活的游戏环境"，输入账号密码即可玩 |

> 记忆：**IaaS 给"硬件"、PaaS 给"环境/平台"、SaaS 给"能直接用的软件"。** 传统 IT = 全自营。

### 1.1.5 云计算的价值（五大特点）

| 价值 | 核心含义 | 生活类比 |
| --- | --- | --- |
| 按需自助服务 | 用户自行下载/购买，基本无需他人协助；前提是了解需求 | 超市自选商品 |
| 广泛的网络接入 | "互联网+计算"，任意设备（PC/Pad/手机）、任意方式（网线/WiFi/流量）均可接入 | 全球互联网覆盖 |
| 资源池化 | 把同类资源汇成池，并**分解到最小单位**，屏蔽不同资源差异 | 自助餐厅按量取用；CPU 最小单位是"核心"，不体现 AMD/Intel |
| 快速部署、弹性伸缩 | 可手动或按策略自动扩容/减容（增减服务器数量，或增减单台资源） | 促销时扩容、热度过后释放 |
| 可计量服务 | 服务可测量（按时间/资源配额/流量），据此自动控制与优化配置 | 用户清晰看到用量 |

> ⚠️ **计量 ≠ 计费**：通过计量可以进行计费，但计量本身不等于计费。多数服务付费，也有免费服务（如弹性伸缩服务大部分时间免费）。

## 1.2 云计算基础技术

三大类：**计算类**（虚拟化、容器）、**网络类**（传统网络、虚拟网络）、**存储类**（块、文件、对象）。

### 1.2.1 计算类技术

#### 虚拟化技术

- 本质：把物理设备**逻辑化**，转化成文件/文件夹（配置信息 + 磁盘文件），实现**软硬件解耦**。
- 效果：一台物理机可同时运行多个虚拟机（VM），每个 VM 有独立操作系统，硬件利用率提高。
- 支持**在线动态迁移**（业务无中断、用户无感知），为 HA（高可用）、DRS（动态资源调度）、DPM（分布式电源管理）等提供可能。

虚拟化的 **4 大特点**：

- **分区**：为 VM 划分底层资源；
- **隔离**：一台 VM 故障/中毒不影响其它 VM；
- **封装**：VM 以文件形式存在，可通过移动/复制文件迁移；
- **独立**：迁移后无需修改即可运行（独立于硬件）。

#### 容器技术

容器（Container）是一种**轻量级的虚拟化技术**，采用**操作系统虚拟化**：把一个操作系统的用户空间分割成多个独立单元在内核中运行，彼此互不干扰。

容器 = 应用程序 + 应用程序运行环境（库等）。**与虚拟机的最大区别：虚拟机额外包含操作系统，容器不包含。**

容器解决了什么问题：软件环境配置复杂（"它在我的机器可以跑了"）；用容器可让应用几乎在任何地方以相同方式运行。

#### 容器 vs 虚拟机

| 维度 | 容器 | 虚拟机 |
| --- | --- | --- |
| 启动速度 | 快（相当于启动本机进程） | 慢（要先启动操作系统） |
| 虚拟化类型 | 操作系统虚拟化（共享宿主机内核）→ 进程级隔离 | 硬件级虚拟化 → 内核级隔离，**安全性更高** |
| 镜像大小 | KB–MB 级 | GB–TB 级 |
| 性能 | 无 Hypervisor 层，性能高、接近原生 | 多虚拟化层，有性能损耗 |
| 系统支持量 | 单机可部署数量多 | 相对少 |

> 容器**没有 Hypervisor 层**（Hypervisor 是运行在物理服务器与 OS 之间的中间软件层），所以被称为"轻量级虚拟化"。
> 镜像 vs 容器：镜像是静态定义（像"类"），容器是镜像运行时的实体（像"实例"）。

### 1.2.2 网络类技术

#### 传统网络基础

- **广播**（一对一发起、广播域内所有人收）与**单播**（一对一）；首次通信常需广播（如 DHCP 用 255.255.255.255）。
- **路由与默认网关**：路由解决广播域之间通信；默认网关是路由的特殊形式，是路由转发的**最后选择**，路由表中无匹配时使用。
- **VLAN**（Virtual Local Area Network，虚拟局域网）：把一个物理 LAN 在逻辑上划分成多个广播域；同 VLAN 可直接通信，不同 VLAN 不能直接通信。好处：限制广播域、增强安全性、提高健壮性、灵活构建虚拟工作组。原理：以太帧中加 4 字节 **802.1Q Tag**。
  - **接入链路（Access Link）**：连主机与交换机，帧为 untagged；**干道链路（Trunk Link）**：连交换机与交换机/路由器，帧为 tagged。
  - 接口分 **Access 接口**（仅过唯一 VLAN）与 **Trunk 接口**（允许多个带 Tag 的 VLAN 帧通过）。

#### 物理设备与 OSI

- OSI 七层：应用层、表示层、会话层、传输层、网络层、数据链路层、物理层。
- **路由 / VLAN**：路由在三层、VLAN 在二层；Hub 不能划 VLAN，是一层设备。
- **路由器与三层交换机**：都工作在网络层。交换机负责高速数据交换（ASIC），适用于局域网；路由器靠软件维护路由表寻址、天生隔离广播域、适用于广域网。三层交换机路由查找针对数据流、性能优于路由器。
- **接入交换机**：流量分业务流量、管理流量、存储流量。带外管理（out-of-band，管理口独立）/ 带内管理（in-band，同一物理通道）。

#### 虚拟网络

- 虚拟交换机把网络接入到服务器内部，与 VM 对接。常见模型：**OVS**（Open vSwitch，开源，内核态处理流量）、**EVS**（增强型虚拟交换机，基于 OVS，用 Intel DPDK 技术在**用户态**处理，IO 性能显著提升）。
- **网桥**：把若干网络接口"连接"起来，主要功能是 **MAC 学习**（建立 CAM 表）与 **报文转发**。
- VM 与外部通信两种方式：**桥接**（网桥像交换机）、**NAT**（网桥像路由器）；桥接/NAT 适用于个人及小规模，不支持 SDN，大规模场景改用虚拟交换机。

### 1.2.3 存储类技术

#### 三大存储类型

| 类型 | 英文 | 特点 | 协议/访问 | 典型场景 |
| --- | --- | --- | --- | --- |
| 块存储 | SAN（Storage Area Network） | 只提供存储空间，文件系统交给客户端；不能多主机共享 | FC SAN；IP SAN：iSCSI / FCIP / FCoE | 数据库等结构化数据、裸设备 |
| 文件存储 | NAS（Network Attached Storage） | 面向客户端的文件级访问，经文件系统格式转换 | CIFS(SMB) / NFS | 文件共享、协同办公；不适合块级、裸设备数据库 |
| 对象存储 | Object Storage | 核心是数据通路与控制通路分离；通过 HTTP/REST 的 URL 访问；扁平命名空间、扩展性强 | HTTP / REST API | 非结构化/静态数据：归档、备份、海量文件共享、数字媒体 |

- 块存储常用来存储结构化数据；数据表示为同等大小的**块**，不赋予比特位含义。
- 文件存储优势：支持全面信息存取、灵活性好（兼容 Linux/Windows）、低成本（以太网组件）。
- 对象存储优点：安全性（内容真实、请求验证在存储设备内）、平台无关性、扩展性（扁平地址空间）、管理性和可靠性（OSD 自愈）。

#### 企业存储的发展

本地磁盘 → **DAS**（直接连接存储，JBOD/RAID）→ 网络存储（**NAS / SAN**，即传统集中式存储）→ **分布式存储**（Ceph、HDFS、FusionStorage、vSAN）。

## 2 华为云介绍

### 2.1 华为云简介

- 定位：**公有云**，凭借华为三十多年 ICT 基础设施积累，提供云与 AI 协同创新、中立安全可信的云服务。
- 公有云建设标准：把数据中心尽量覆盖所有主要城市，降低就近接入时延。

华为云的几点优势：

| 优势 | 要点 |
| --- | --- |
| 节点优势 | 国内遵循 **"2+7+N"** 架构：2 个一级中心（乌兰察布、贵阳，每个一级中心 3 个 AZ、相隔 30–50 公里）、7 个区域中心（华北/华东/华南/香港等主力 region）、N 个卫星节点（政务云 + 公有云节点）。海外与伙伴在全球 23 个地理区域运营 45 个可用区 |
| 云服务数量多 | 已上线 200+ 云服务、2800+ 云市场应用、6000+ 合作伙伴 |
| 芯片优势 | 华为硬件起家，端到端软硬支撑；推出计算、网络、存储、安全全系列芯片 |
| 擎天架构 + 瑶光云脑 | 擎天架构含数据面"软硬协同系统"与管控面"智慧云脑"；支持共享存储裸金属、千万级 PPS、40G 带宽裸金属等创新 |
| 瑶光云脑能力 | 全域调度、动态协商与治理、多目标优化、多样算力（鲲鹏/昇腾/x86/GPU/FPGA）、全栈可信 |

### 2.2 应用场景（四种解决方案）

- **企业上云中心**：覆盖迁移上云、企业初创、建站、数据、管理、出海、运输管理等；
- **行业解决方案**：深耕不同行业实际需求；
- **通用解决方案**：预集成产品与能力组合；
- **组织解决方案**：面向企业、公益/非盈利机构、HMS 生态伙伴。

### 2.3 交付模式（三种）

| 交付模式 | 说明 | 适用对象 |
| --- | --- | --- |
| 公有云 | 个人/企业直接在华为云门户自助购买、通过互联网使用 | 任何有 IT 资源需求的个人或企业 |
| 华为云 Stack | 部署在客户本地数据中心的云基础设施，**混合云**模式交付 | 数据要求本地化存储 / 设备须物理隔离的中大型政企 |
| 边缘云 | 基于覆盖中国大陆主要省市的优质节点部署，时延敏感业务就近接入（<10ms） | 互动娱乐、在线教育、媒体创作等时延敏感业务 |

### 2.4 技术支持

三大类服务体系：**新手入门**（图说云服务、初学者课程、典型场景最佳实践、专家技术汇）、**客户支持**（多种咨询沟通通道）、**增值服务**（培训认证等专业服务）。

### 2.5 华为云生态

理念：**共创、共享、共赢**。

- 共创：构建应用使能、数据使能、AI 使能三大平台；
- 共享：通过擎天架构打通公有云、混合云、边缘云，构建统一应用生态；
- 共赢：与伙伴共同为客户创造价值。

伙伴分两类：**咨询类伙伴**（咨询公司、经销商、SI 等）与**技术类伙伴**（ISV、SaaS、PaaS、开发工具、管理和安全供应商等）。此外还有华为云云市场（Marketplace）作为应用分发与交易平台。

### 2.6 华为云快速入门

**计费模式**：

| 计费模式 | 付费类型 | 说明 |
| --- | --- | --- |
| 按需计费 | 后付费 | 按实际使用时长计费，可随时开通/删除 |
| 包月/包年 | 预付费 | 按购买周期计费，适合可预估使用周期，价格更优惠 |
| 竞价计费 | 后付费 | 以更低折扣按实际使用时长计费 |

**区域与可用区**：

- **区域（Region）**：从地理位置和网络时延维度划分，通常以城市为单位；同一 Region 内共享弹性计算、块存储、对象存储、VPC、EIP、镜像等公共服务。分通用 Region 与专属 Region。
- **可用区（AZ，Availability Zone）**：一个 AZ 是一个或多个物理数据中心的集合，有独立的风火水电；同 Region 的多个 AZ 间通过高速光纤相连。

选择原则：**就近选 Region 减少时延；对容灾要求高→资源放同 Region 不同 AZ；对时延要求低→放同一 AZ。**（可把同 Region 不同 AZ 理解为"同城不同机房"）

**IAM（统一身份认证服务）**：基于主账号创建 IAM 用户分配给他人，避免主账号密码泄露并管控资源使用。

| 概念 | 归属 | 特点 |
| --- | --- | --- |
| 项目（Project） | IAM | 对**同一 Region 内**资源分组隔离；**物理隔离**；资源不能转移，只能删除后重建 |
| 企业项目 | 企业管理服务 | 可包含**多个 Region** 资源；资源可迁入迁出；是 IAM 项目的升级版，推荐使用 |

> 开通企业管理后将不能创建新的 IAM 项目（只能管理已有项目）；未来 IAM 项目将逐渐被企业项目替代。

## 核心概念速查表

| 术语 | 含义 |
| --- | --- |

## 考点 / 易错点

- **定义细节**：云计算是"模型"不是"技术"（虚拟化才是技术）。"随时随地"的前提是**网络可达**。
- **部署模式 vs 服务模式**：公有/私有/混合/行业云是**部署模式**；IaaS/PaaS/SaaS 是**服务（运营）模式**，别混淆。
- **数据中心等级对应**：IaaS → 基础设施层；PaaS → 基础设施层 + 平台层；SaaS → 全部。
- **计量 ≠ 计费**：常考判断题。
- **容器与虚拟机**：容器虚拟的是**操作系统**，无 Hypervisor，进程级隔离、安全性比虚拟机低；虚拟机是硬件级虚拟化、内核级隔离。
- **VLAN**：不同 VLAN 不能直接通信；Access 口发出去的帧永远不带 Tag。
- **"2+7+N"**：2 = 乌兰察布、贵阳一级中心（每个 3 AZ）；7 = 区域中心；N = 卫星节点。
- **IAM 项目 vs 企业项目**：IAM 项目物理隔离、不可迁移、限同 Region；企业项目可跨 Region、可迁移。
- **华为云 Stack 属混合云模式交付**，不是公有云。

## 自测题

1. 云计算的权威定义由哪个机构提出？定义中的资源包括哪些？
2. 判断：云计算是一种技术。（×）请说明云计算的准确定位，并说明虚拟化的准确定位。
3. 一位用户购买的是"已安装好运行环境（如 .NET Framework）"的云服务，这属于 IaaS、PaaS 还是 SaaS？
4. 云计算的五大价值（特点）分别是什么？"计量"与"计费"是什么关系？
5. 简述容器与虚拟机的三点主要区别；为什么说容器是"轻量级"虚拟化？
6. 华为云"2+7+N"中的"2""7""N"分别指什么？Region 与 AZ 的区别是什么？

1. 美国国家标准与技术研究院（NIST）。资源包括网络、服务器、存储、应用及服务等。

5. ① 启动速度：容器快、虚拟机慢；② 虚拟化类型/隔离：容器是操作系统虚拟化（进程级隔离），虚拟机是硬件级虚拟化（内核级隔离）；③ 镜像大小：容器 KB–MB 级，虚拟机 GB–TB 级（另有性能、系统支持量等）。因为容器没有 Hypervisor 层、共享宿主机内核，所以称轻量级虚拟化。
6. "2" = 乌兰察布、贵阳两个一级中心（每个含 3 个 AZ）；"7" = 华北/华东/华南/香港等区域中心（主力 region）；"N" = 卫星节点（用于政务云 + 公有云节点）。Region 从地理位置和网络时延维度划分（城市级），同一 Region 内共享弹性计算、块存储、对象存储、VPC、EIP、镜像等公共服务；AZ 是 Region 往下一级，是一个或多个物理数据中心的集合，有独立的风火水电，同 Region 多 AZ 间通过高速光纤相连。
